# 履修要件・特別プログラム判定モデル

## 目的

時間割に登録された授業を単純に合計するのではなく、次の4層を分けて扱う。

1. **履修実績**: 科目コード・科目名・単位・成績・開講位置
2. **所属学科の卒業要件**: 区分ごとの必要単位と該当科目
3. **進級・卒業研究着手条件**: 卒業要件とは別の節目条件
4. **特別プログラム**: ひらめき、TAP、ATAP、TUCPなどの追加条件

特別プログラムを学科カリキュラムの代わりとして扱わない。通常カリキュラムに対する「オーバーレイ」として扱う。

## 正本とデータ優先順位

判定に使う情報の優先順位は次の通り。

1. 入学年度別の履修要綱・教育課程表
2. 大学公式のプログラム別リーフレット、募集要項、ハンドブック
3. `public/department/{facultyId}/{entranceYear}/` 配下の確認済みCSV
4. 科目CSVのカテゴリ・タグから導出した暫定候補
5. 学生が手入力した情報

4と5を使った判定は、画面上で「暫定」「追加確認が必要」と明示する。

## 履修実績の正規化

`src/core/courseRecords.ts` が全学年・全クォーターの時間割セルを走査し、1科目1レコードへ正規化する。

照合順序:

1. 科目ID
2. 講義コード
3. 科目名
4. 別名

同一科目が複数クォーターまたは複数学年に存在する場合は、次の優先順位で1件にまとめる。

1. 取得済
2. 履修予定
3. 不可

これにより、同じ授業を時間割へ複数回登録した場合の単位二重計上を防ぐ。

## 卒業要件の割り当て

`src/api/requirements.ts` は該当科目CSVを使い、履修実績を卒業要件区分へ割り当てる。

- 1つの履修実績を複数区分へ同時に加算しない。
- 取得済を履修予定より先に割り当てる。
- 区分の必要単位を満たした後の超過単位は、自由選択区分へ回す。
- 該当科目CSVがない区分だけ、科目カテゴリ・グループから暫定候補を生成する。
- 不可は取得済・履修予定へ加算しない。

## 進級・卒業研究着手条件

卒業要件CSVの `stage` が `卒業` 以外の行を、別パネルで表示する。

数値化されている単位条件は自動判定する。次のような条件は自動で断定しない。

- 在学期間
- 学科固有条件
- 卒業研究着手に必要な個別必修科目
- 要綱本文だけに書かれた例外

これらは「追加確認が必要」とする。

## 特別プログラム

### ひらめき

科目名・タグから以下の科目群を検索し、取得済・履修予定単位を表示する。

- ひらめきづくり
- ことづくり
- ものづくり
- くらしづくり
- ひとづくり
- Next PBL / SD PBL
- AI・データサイエンス

修了可否は入学年度・学部・学科別リーフレットを正本とし、アプリでは断定しない。

### TAP

手入力と履修実績から次を確認する。

- 語学準備講座の出席率
- 語学準備講座の合否
- 前期・後期の取得単位
- サイクルA/Bと履修予定クォーターの重複

### ATAP

- 現在のGPA
- IELTS / TOEFL iBT
- 単位認定区分の個別確認

### TUCP

- TOEIC
- 秋学期側の履修予定との重複
- 単位認定区分の個別確認

## 追加すべきデータ

完成度を上げるには、次のデータを入学年度単位で追加する。

- 後期を含む年間開講時間割
- ひらめきの学部・学科別修了要件CSV
- TAP / ATAP / TUCPの認定科目・認定区分CSV
- 学科固有の進級必修・卒業研究着手必修
- 科目改称・科目コード変更の別名対応表
