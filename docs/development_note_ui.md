# Campus Note UI再設計

更新: 2026-09-05

## 問題と設計判断

旧画面は卒業リスクと未判定表示が重複し、6項目のナビゲーションに実質同じ資料画面が2つあった。科目検索は参照だけで、見つけた科目を時間割に追加できなかった。成績画面も多数の分析カードを先に出し、入力は別画面へ戻る必要があった。

ホーム・時間割・成績／単位・履修ガイドの4画面に整理。設定・バックアップはヘッダーから到達する。ホームは今期の予定と次の操作を中心にし、未入力GPAはダッシュ表示。学科・入学年度の初回確認と、表示学年の意味を説明する。確認状態だけを新しいlocalStorageキーに保存し、既存の時間割・成績とSQLiteは引き継ぐ。

科目追加は検索→追加→空きコマ→編集ダイアログ→保存。開講時間を推測しない。登録済みコマへの追加を拒否し、学科・入学年度・表示学年・Qの変更時に古い選択を破棄する。新しい編集画面はnative dialogを用い、フォーカス管理とEscを備える。詳細情報は折りたたむ。

成績は学年ごとの科目行に直接入力できる。同一学年・科目ID（なければ正規化名称）が一致する複数Qの記録をまとめて更新。GPA・単位集計の重複も抑制した。入力済み合格単位 `recordedEarnedCredits` と既存の分類済み `earnedCredits` を区別し、未確認科目を卒業要件へ自動算入しない。

## デザインの参照

[google-labs-code/design.md](https://github.com/google-labs-code/design.md) の「機械可読トークン＋設計意図」という構成を参考に [DESIGN.md](../DESIGN.md) を作成。青緑の主操作、白いカード、最大1280px、4項目ナビ、44px操作領域、段階的な情報開示を定義した。新しいCSSは `src/student.css`。デザインCLIの導入や外部デプロイは行っていない。

## 検証

- TypeScript/Viteビルド、新規・再設計コンポーネントのESLint。
- Nodeテスト8件。新規2件は複数Qの同一科目、未確認区分の合格、未入力・不可、卒業未判定の維持。
- Chromeで初回確認→科目検索→空きコマ→保存→成績「優」の入力→1単位・GPA3.00表示。
- 390pxで科目追加・既存コマの上書き拒否・ページ全体の横はみ出しなしを確認。
- 検証はlocalhost側のブラウザー保存領域を利用し、利用者の127.0.0.1側の記録と分離。

実学生によるユーザビリティテスト、Claude Code・担当者レビューは未実施。全科目の必選・算入条件の原本承認は別の未完了事項であり、このUI変更で卒業判定が完成したとは扱わない。既存の全文Lint負債も全解消したとはしていない。
