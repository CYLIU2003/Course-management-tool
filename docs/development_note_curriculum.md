# 公式履修資料・SQLite統合 開発ノート

更新日: 2026-09-05。ブランチ: `feature/official-handbooks-2022-onward`。

## 変更と使い方

「履修資料」を追加。学科と入学年度を選ぶと、該当する共通分野・学科・学部・教職課程の要覧を選択する。一般の学部生を基本とし、ひらめき、TAP／ATAP、教職の3フラグを独立して保存する。未選択、単独、任意の2つ、全部の8通りに対応し、プログラム同士の排他制約は設けていない。選択して保存すると専用タブが表示される。TAP／ATAPは同一の追加プログラム枠で、その中の両方の公式説明を確認できる。

ひらめきは対象年度・学部・学科でパンフレットを絞り込む。2025年は理工学部と他6学部で別資料、2026年は基礎プログラム12単位。基礎プログラムは科目名・単位数・合格評価が一致したものを照合し、複数Qの重複を除く。旧年度の124単位はプログラム内訳であり卒業単位に追加で124単位を課すものではない。

TAP／ATAPは要覧本文を全角英数字正規化後に分類し、学修内容・参加条件・認定科目表・履修制限・学科固有の注意を原本ページに結び付けた。該当ページ数は2022年69、2023年65、2024年75、2025年67、2026年71（目次・履修モデル等も含む）。教学課FAQのTAP辞退者向け説明は、現在のFAQとして別に保存し、入学年度の要件に混ぜない。

- 原本125件、5,887ページ、24,181科目レコード（旧抽出18,890行と番号座標復元5,291行、重複を含む）、2,651原表。科目行は重複・複数学科を含むため、大学の一意な科目数ではない。

## SQLiteとデータモデル

正本DBは `data/curriculum.sqlite3`（約51MB）。`CURRICULUM_DB_PATH` で別パスを指定できる。SQLiteファイルとWALは学生設定を含みGit対象外。原本と抽出JSONは `public/handbooks/` にあり、JSONは再インポート用成果物。アプリの履修資料APIはSQLiteを読み、DB障害時に古いJSONに切り替えない。

| テーブル | 内容 |
|---|---|
| faculties / departments | 学部・学科 |
| source_documents / source_pages | 原本識別・ハッシュ・年度・全ページ本文・トピック |
| source_tables / course_records | 原表セル・座標、科目名・単位・必選原表記・ページ参照 |
| requirement_evidence | 卒業、進級、登録、教職、ひらめき、TAPの出典ページ索引 |
| programs / program_groups / program_courses | 年度別ひらめき対象・科目群必要単位・科目 |
| web_evidence | 教学課FAQの取得記録と抽出問答 |
| student_profiles | 学科・入学年度・3プログラムの選択・保存リビジョン |
| dataset_meta | スキーマ・取得・インポート情報 |
| cohort_datasets | 学科・入学年度ごとの検証済み参照候補、判定可否 |
| academic_calendars | ICS用学年暦 |

外部キー、単位・真偽値CHECK制約、トランザクション、WAL、10秒busy timeoutを使用。再インポートは参照データのみを単一トランザクションで置換し、学生設定を保持する。原本ハッシュ・ページ数・抽出行数が不一致ならロールバック。プロフィールはリビジョンによる楽観ロックで競合時409を返す。DB接続・バックアップ接続は明示的に閉じる。

プロフィールIDだけをブラウザーに保存する。既存の時間割・成績は従来どおりlocalStorageで、今回SQLiteへ移していない。ブラウザーのサイトデータを消すとプロフィールIDの紐付けも消える。個人利用のローカルAPIで、認証付き多人数サーバーではない。127.0.0.1のみ待ち受ける。

## 再収集と更新

```powershell
python -m pip install -r scripts/curriculum/requirements.txt
python scripts/curriculum/collect_handbooks.py
python scripts/curriculum/extract_handbooks.py
python scripts/curriculum/verify_pdf_courses.py
python scripts/curriculum/test_pdf_courses.py
python scripts/curriculum/build_hirameki.py
python scripts/curriculum/collect_tap.py
npm run db:build
python scripts/curriculum/audit_database.py
npm run test:handbooks
npm run test:database
npm run build
```

PDF文字抽出の一部は、ToUnicodeが欠落した2023年資料の埋込フォントを、WindowsのMS明朝・MSゴシック・游書体の同一グリフ輪郭で照合して復元する。推測OCRではなく、一致した文字だけを採用し、対応フォントのハッシュと不一致数を残す。この再抽出には該当Windowsフォントが必要。別OSでも配布済み抽出JSONからSQLiteの再構築とアプリ実行は可能。

PDFダウンロードだけを並列化し、PyMuPDF処理は直列で行う。抽出パーサーハッシュと原本ハッシュに基づきキャッシュを無効化する。新年度やサイト構造が変わったら収録対象・対象学科・ひらめきの手動確認済み内訳を見直す。翌年度の要件へ自動流用しない。

既存PDFは通常再利用する。同じ大学URLのPDFが改訂された場合は原本アーカイブをバックアップし、`python scripts/curriculum/collect_handbooks.py --refresh` で再取得してから後続の抽出・検証を実行する。ひらめきは確認済みファイルと年度の対応表で紐付け、リンク順が変わっても年度を取り違えない。未確認の新しいリンクや件数変更は停止して人手確認を要求する。

## バックアップ

```powershell
python -m backend.database --backup data/backup-20260905.sqlite3
npm run db:check
```

SQLiteのbackup APIでWALの内容も含む整合したスナップショットを作成する。同名ファイルは上書きしない。復旧時はアプリを停止し、`CURRICULUM_DB_PATH` をバックアップファイルに向けて起動する。資料PDFはDBにBLOBとして埋め込まずパスとハッシュを保持するため、移行・バックアップには `public/handbooks/` と抽出物も併せて保存する。

## 判定の範囲と未確定事項

**これは全科目・全条件を自動認定できる卒業／免許取得判定エンジンの完成ではない。** 全文・原表をDBへ収録し、年度別の参照・検索と一部ひらめき科目の照合を提供する段階。

結合セル、学科別必選記号、読み替え、選択群、免許教科別条件など、解釈を確定できない1,069行は `extraction-issues.json` に残した。全科目レコードは `extracted_reference` とし、自動的に卒業要件の必修へ昇格させない。106ページはテキストがなく、表紙・裏表紙や空白ページを含む。描画を持つものは先頭／最終ページで、サンプルは輪郭文字の表紙だった。原本ページを必ず参照可能にしてある。

全年度の科目検索・要件データは `cohort_datasets` を `/api/curricula/{departmentId}/{entranceYear}` から読む。旧CSVの科目・時間割・要件は現行DBビルドにも混ぜない。2026年度の旧CSV要件も原本条件との照合が済んでいないため外し、全94収録組み合わせを `partial/referenceOnly` として不足単位・卒業達成を未判定にする。TAP認定・教職算入・ひらめき旧年度記号の全自動計算は未実装。参加フラグだけで成績や取得単位を作らない。

大学ポータルの文書ライブラリに掲載される正誤表は公開索引から取得できないため未収録。公式要件の変更は各自の入学年度の要覧と正誤表で確認する。

- **P1 修正**: 人間科学部・都市生活学部でG注記や「講義」「演習」が科目名に混入。原本の独立した文字列と照合して名称を分離。2022年度人間科学部の原本名「児童学科」に対応。
- **P1 修正**: 情報科学科2024 PDF4ページなど結合見出しで教育課程表が脱落。科目番号、同一行の科目名、縦書き単位見出しの座標を用いた復元を追加。「数学演習(1a) 0.5単位」を原本画像で確認。
- **P1 修正**: 到達目標・免許・測量士等の表の混入と、環境／メディア学部内の他学科混入を除去。原本見出しから学部共通・個別学科・連続ページを区別。
- **P1 修正**: 不足要件0のとき「達成済み」と出る表示を修正。空の必選区分を「なし」とは表示しない。
- **P1 修正**: フロントの旧CSV自動読み込み・手動マスター上書き入口を削除。JSON復元でもDB要件を上書きしない。SQLite取り込み時に原本SHA、科目名、単位、年度、対象学科を再検査する。

### 照合データと再現性

`verification` に原本SHA-256、ページ、タイトルbbox、単位見出しbbox、単位数字のbbox、適用範囲を保存。照合不能行は `quarantined` とし、原表を削除せず自動候補から除外する。照合の集計は [pdf-course-verification.json](pdf-course-verification.json)、先頭文字修復は [title-repair-audit.json](title-repair-audit.json)。

24,181レコード中17,725行が文字位置検査に合格、6,456行が通常科目候補から除外。5,291行は番号座標からの復元行で、旧抽出と同じ科目の行も含むため「新たに発見した一意な科目数」ではない。API候補は名称・単位で重複を整理し、単位が衝突すれば採用しない。

**文字位置検査は全科目・全履修条件の人手承認ではない。** 全125資料の原本ハッシュと既存抽出行を機械検査し、今回の画像目視は機械2024 PDF4、情報科学2024 PDF4、人間2024 PDF56、都市生活2024 PDF62。多段・複数行の名称、番号のない行、コース別必選、履修不可記号、卒業単位への算入、正誤表は追加確認が必要。科目検索は学科の教育課程表に掲載された参照候補で、本人の履修許可やコース別必修の確定ではない。

### SQLite v2

`cohort_datasets`（19選択肢×5年度=95件）と `academic_calendars` を追加。v1からの追加マイグレーションは学生プロフィールを保持する。API起動後のヘルス確認でv2・95件を確認してからViteを起動する。`npm run preview`もAPIを併用する。`data/import/curricula.json`には全入力のSHAを保存し、古い抽出JSONとの組み合わせを拒否する。CSVからの実行時・ビルド時補完はない。
