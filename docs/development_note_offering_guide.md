# v0.1.1 教員・教場入力と履修ガイド（2026-09-05）

## 変更

SQLiteの `scheduled_offerings.payload_json` とSupabaseの開講snapshotに教員・教場が保存されていたが、時間割編集画面が参照していなかった。

- 科目名・学科/キャンパス・曜日・時限・クォーターに一致する2026年度のクラスを表示。クラス選択で教員・教場・講義コード・開講期・対象を自動入力する。
- 訂正確認中の講義は候補から除外し、同名科目の先頭候補を勝手に入力しない。開講年度2026を明示して `sourceOffering.academicYear` に保存する。
- 科目変更時に前の科目の教員・教場・成績・単位・出典を残さない。
- 履修ガイドに区分別の科目・単位・修得済み/予定/不合格/単位数要確認/未登録を表示。複数コマ・複数Qの同一科目を重複加算しない。
- 必要単位はDB内の卒業要件表の一致行に明示され、数値矛盾がない場合のみ表示。内訳・原本ページを併記する。未確認値は0にしない。予定単位を修得済みに含めない。
- 既存のSupabase/SQLite APIを再利用。CSV参照・スキーマ変更・参照データ再投入は不要。

## 原本・検証

- [世田谷2026](https://www.asc.tcu.ac.jp/7567/)・[横浜2026](https://www.asc.tcu.ac.jp/7580/)の添付集合が保存manifestと一致。35資料の再取得SHA-256も全件一致。
- DBは3,706講義コード、5,468会合。教員記載5,466会合、教場記載3,188会合。原本にない値を補完していない。
- 全学科前期PDF44ページの `saz001107`（線形代数学(1)、井上浩一、11A）、2022機械PDF7ページの基礎30単位・専門60単位をレンダリングして照合。
- `test:offering-guide` は年度・曜日時限・Q・訂正状態、原本必要単位、重複集計、不合格・予定・単位不一致を検証。公開verifyに追加。
- TypeScript・変更モジュールのESLintを通過。ローカルブラウザの検証用データで「修得1 / 必要30 / 残り29」とクラス選択後の保存値「井上浩一・11A・2026」を確認。実ユーザーの履修記録は変更していない。
