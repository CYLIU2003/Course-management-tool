# 2026年度開講情報の取込・照合

2026-09-05取得。[世田谷](https://www.asc.tcu.ac.jp/7567/)と[横浜](https://www.asc.tcu.ac.jp/7580/)の本文にある添付資料を収集した。リンクのURL重複を排除し、35添付（34 PDF、1 DOCX）、33,986,318 bytesを保存。HTMLスナップショット、取得URL、SHA-256は`public/offerings/2026/catalog.json`。

## 件数の意味

全学科前期・後期、横浜学部全期、各大学院の基準時間表6資料を使い、講義コードの掲載8,576箇所に対して抽出8,576行。科目名・学科空欄は0行。年度＋講義コードを一意キーにすると3,702講義、訂正資料にのみ掲載された4コードを加えて3,706講義。重複キーは0件。

「掲載行数」は授業数ではない。同じ授業の連続時限、別クラス、別学科への掲載を、出典行・開講時限・受講対象として保持する。授業時間表と入学年度別卒業要件は別データであり、時間表から必要単位や卒業認定を推測しない。

学科別前期PDFは全学科版より古い別版として保存し、単純加算しない。大学院の旧128行資料の全講義コードが新資料に収録されていることを検査した。原本・抽出ページ・座標・旧版自体はSQLiteに保持して比較できる。

## 訂正と未解決事項

訂正一覧165レコードを出典ページ、日付、修正前後、原文セル付きで保持する。単純な科目名・教室・教員・時限変更のみ、修正前の一致とキャンパス・開講期を確認して反映する。四半期限定の修正を学期全体に広げない。

**97講義は条件付き訂正・開講追加等の確認が残る。現時点で「過不足なく確定した2026時間割」は未達。** 該当講義は`correction_review_required`または`correction_only`として表示する。初回のみの教室、日付限定、複数フィールドの変更等を一律に適用しない。訂正のみの4コードは未確定の曜日・時限を捏造せず空欄で保持する。全ての資料情報の保存と、全ての履修ルールの確定を区別する。

講義コード全掲載箇所の照合は抽出漏れを検出する検査であり、8,576行全フィールドの人手照合ではない。全文・表の保存は済んでいるが、注意事項やDOCXの全内容を構造化した履修ルールにはしていない。

## 再現手順

```powershell
python -m scripts.curriculum.collect_offerings
python -m scripts.curriculum.extract_offerings
python -m scripts.curriculum.import_offerings
python -m unittest backend.test_offerings -v
```

取込は原本SHAを検査し、2026年度の対象テーブルを単一SQLiteトランザクションで更新。再実行しても講義キーが増殖しない。利用者アカウント・成績は更新しない。`offering_sources`は資料、`offering_occurrences`は出典行、`scheduled_offerings`は講義、`offering_imports`は訂正と検査結果。

結果は`docs/offerings-2026-audit.json`。APIは`/api/offerings/2026`と`/api/offerings/2026/audit`。フロントは学科・期・科目名・講義コードで絞り込み、原本ページと訂正原文を確認できる。公開版はSQLiteからエクスポートした同じ内容をSupabaseから取得する。
